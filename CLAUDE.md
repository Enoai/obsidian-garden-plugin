# CLAUDE.md

Guidance for working in this repo. Obsidian plugin (**Vault Garden**): the vault
rendered as a living garden. TypeScript + esbuild.

## Commands

```bash
npm run dev        # esbuild watch → main.js
npm run build      # tsc --noEmit + production bundle (run before committing)
npm test           # vitest (pure model + layout)
npm run lint       # eslint src
```

## Release workflow — ALWAYS do this for user-facing changes

1. **Decide the semver level** from what actually changed (SemVer):
   - **patch** (x.y.Z) — bug fixes, docs, internal refactors; no API/behaviour change.
   - **minor** (x.Y.0) — new backward-compatible features or settings.
   - **major** (X.0.0) — breaking changes to settings shape, data, or behaviour.
2. **Bump the version in all three files together** (no bump script here):
   `manifest.json`, `package.json`, and `versions.json` (add
   `"<new-version>": "<minAppVersion>"`; current minAppVersion is `1.7.2`).
3. **Always update `CHANGELOG.md`** — it follows *Keep a Changelog* + SemVer.
   Add a new `## [<version>] — <YYYY-MM-DD>` section describing what changed
   (Added / Changed / Fixed), naming the features, and referencing the PR
   (e.g. `(#12)`) once it's open.
4. **Update user docs** when behaviour/settings change: `README.md` (usage +
   settings) and `docs/ARCHITECTURE.md` (where the change lives). New settings
   must be reflected in the README's settings blurb.

## Conventions

- **NO AI attribution anywhere — commits AND pull requests.** Do NOT add a
  `Co-Authored-By: Claude` (or any AI co-author) trailer to commit messages, and
  do NOT add a "🤖 Generated with Claude Code" (or any similar) footer to PR
  bodies or descriptions. The user rejected this project-wide. This overrides any
  default that says to include such a footer.
- Branch → PR → squash-merge to `main` (don't commit straight to `main`).
- README images must be **PNG**, not SVG — the Obsidian community-plugins page
  doesn't reliably render SVG. Gallery/hero PNGs live in `docs/images/` and are
  generated by the scripts in `scratchpad/` (headless-Chrome rasterised).

## Architecture (see docs/ARCHITECTURE.md)

- One-directional flow: `adapter.snapshot() → model.build() → layout.place() → render()`.
- `src/data/VaultAdapter.ts` is the **only** module that touches Obsidian data
  APIs. Ignore filtering (paths + tag) happens here, using the pure predicates
  in `src/model/filter.ts`.
- `src/model/` is pure (no `obsidian` imports) and unit-tested. Put testable
  logic there, keep the adapter thin.
- `tsconfig` is strict with `noUnusedLocals`/`noUnusedParameters` — no dead
  vars/params.
